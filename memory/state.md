# Текущий статус

Обновлено: **2026-10-01**, пользовательская временная зона Europe/Moscow.

## Стадия

R0 — оформление архитектурного контекста. Последняя концепция принята пользователем как текущая база проекта. Перед реализацией пользователь просит показать Memory Bank и дождаться подтверждения продолжения.

## Что существует

- Папка проекта `memecoin-ai`, выбранная пользователем в проектах Codex.
- Memory Bank из связанных Markdown-документов, точка входа `AGENTS.md` и корневой README.
- Реестр D01–D17 и план E01–E14.
- История пересмотра концепции, список открытых параметров, roadmap и источники.
- `.gitignore` для локальных данных, весов, секретов и тяжёлых артефактов.
- Локальный Git-репозиторий с начальной веткой `main`; remote не настроен.

Результаты проверки создания фиксируются в последней записи [changes.md](changes.md). Наличие Git не подразумевает remote или публикацию. Точную историю коммитов читать из Git, не из вручную дублируемых hash в документах.

## Что не существует

Нет collector, dataset, feature pipeline, simulator, обученной модели, experiment results, benchmark M4, paper bot и live execution. Ни один опыт E01–E14 не проведён. Источник данных не выбран, edge не установлен.

## Текущие выборы

Приняты: независимая от LLM PyTorch-система, point-in-time данные, реалистичное исполнение, независимый risk layer, временная оценка, необязательность RL, широкое наблюдение при ограниченном первом execution domain, версионированный retraining.

Не зафиксированы: backbone, size, scanner/K, temporal format, cross-token/graph architecture, horizons/frequency, sizing, конкретный рынок внутри Solana, провайдер, капитал, валюта primary objective, риск-пороги и promotion thresholds. Актуальные причины и сравнения — [decisions.md](decisions.md), не старые численные рекомендации из обсуждения.

## Следующий разрешённый шаг

Показать пользователю структуру и содержание Memory Bank. До нового подтверждения не начинать торговую реализацию. После него первая задача — R1 research specification и R2 аудит доступных данных, а не установка сложного модельного стека.

## Открытые зависимости

Параметры, требующие определения, перечислены в [project.md](project.md). Не запрашивать их все автоматически в новой сессии: сначала проверить актуальное поручение, доступные данные и какие ответы действительно нужны текущему этапу.

## Условия обновления

После подтверждения пользователя заменить ограничение стадии на конкретно разрешённый scope и записать изменение в историю. По завершении существенной работы обновлять фактические результаты и следующий шаг. Не сохранять устаревшее ожидание подтверждения после того, как оно получено.
