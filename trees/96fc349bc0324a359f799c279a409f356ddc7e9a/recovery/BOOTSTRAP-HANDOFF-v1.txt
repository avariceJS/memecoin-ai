BRAIN BOOTSTRAP HANDOFF v1 — BEFORE USING KINGSTON

Purpose
=======
This handoff authorizes only retrieval of one exact research-code commit and comparison of one
versioned Kingston entry card. It does not accept a recovery set, Data source cutoff T, Kingston
frontier K, restored Brain state, service activation, or erase readiness.

Trust source
============
Use the authenticated repository remote below. This assumes the Git account and remote remain
available and uncompromised; the tag is not a cryptographic signature. Do not use the moving branch
head as the accepted code target. H is the commit reached by the annotated tag; C is the separately
pinned bootstrap commit in BOOTSTRAP-HANDOFF-v1.json. Never move the v1 tag; later handoffs use new
versioned tags.

   REMOTE=https://github.com/avariceJS/memecoin-ai.git
   TAG_REF=refs/tags/brain-dr-handoff-v1

On the replacement Mac, sign in to Git through its normal user-controlled authentication flow. Use
host-installed Git to retrieve and inspect the tag before reading or running any Kingston card
command. In a new private temporary directory:

   umask 077
   HANDOFF_DIR=$(mktemp -d "$HOME/brain-handoff-v1.XXXXXX") || exit 2
   chmod 700 "$HANDOFF_DIR"
   git -C "$HANDOFF_DIR" init || exit 2
   git -C "$HANDOFF_DIR" remote add origin "$REMOTE" || exit 2
   git -c http.version=HTTP/1.1 -C "$HANDOFF_DIR" fetch --no-tags origin \
     "$TAG_REF:$TAG_REF" || exit 2
   test "$(git -C "$HANDOFF_DIR" cat-file -t "$TAG_REF")" = tag || exit 2
   TAG_OBJECT=$(git -C "$HANDOFF_DIR" rev-parse "$TAG_REF") || exit 2
   HANDOFF_COMMIT=$(git -C "$HANDOFF_DIR" rev-parse "$TAG_REF^{}") || exit 2
   git -C "$HANDOFF_DIR" cat-file tag "$TAG_REF"
   git -C "$HANDOFF_DIR" show "$HANDOFF_COMMIT:recovery/BOOTSTRAP-HANDOFF-v1.json" \
     > "$HANDOFF_DIR/handoff.json" || exit 2
   chmod 600 "$HANDOFF_DIR/handoff.json"
   HANDOFF_SHA256=$(shasum -a 256 "$HANDOFF_DIR/handoff.json" | cut -d ' ' -f 1)

Record TAG_OBJECT, HANDOFF_COMMIT, and HANDOFF_SHA256 in the local recovery notes. Verify the
handoff schema, tag ref, exact C, card relative path and SHA-256, remote URL, Kingston volume UUID
and BrainData root ID, and all false/unavailable recovery and authority fields. The v1 tag must be
annotated. A missing, lightweight, malformed, or unexpected tag/handoff blocks recovery. These
checks identify and pin the fetched Git objects; they cannot detect a tag retarget performed by an
administrator of the same remote. The no-move publication policy and the authenticated origin are
the trust boundary.

Only after the handoff checks pass, inspect Kingston read-only and calculate the card digest using
the exact path named by the handoff:

   shasum -a 256 /Volumes/Kingston/BrainData/host-recovery/ENTRY-v2.txt

Proceed only if it equals the authenticated handoff's entry_card_sha256. Then follow that exact
card. Do not substitute legacy ENTRY.txt, another tag, a moving branch tip, or values copied only
from Kingston. The v2 card independently compares its source checkout bytes against Kingston and
runs the exact-commit inert code bootstrap.

The local HANDOFF_SHA256 comes from the file extracted from the fetched Git commit. It is supplied
separately from the local handoff path if a later restore-flow operation needs a handoff digest;
it is not stored as the only pin beside that file. This bootstrap-only handoff is not a restore
handoff and cannot be passed to the post-bootstrap restore flow.
