# Control Center workflow after consolidation

Follow ONBOARDING.md and the app AGENTS. This workflow is opt-in for a UI task, not a global
research orchestrator. The integrated main retains both the Brain and read-only Observatory.

WORK_STATE.json retains the CC02 dependency graph, bounded file leases, required boundary and
visual reviews, and incomplete status. STATUS.md is generated by scripts/workflow.py --render.
Use --check to validate consistency. The default Git scope guard checks pending edits against
HEAD; use check_scope.py --base REF for a committed UI-only review range. A core integration
is separately reviewed under root rules; it must not be misrepresented as a UI-only change.

Select the next authorized ready task, assign bounded ownership if delegation helps, implement,
run checks, inspect evidence, update state and commit explicit paths. Do not automatically
start CC02 while performing an unrelated Git/research task. Grok is disabled; no mandatory
model/team loop or claim that a model was verified. Session-selected bindings remain UNVERIFIED.

For visual tasks, first inspect primary and before images. Preserve before/fix/second screenshots,
viewport matrix and independent visual critique. Failed reference/receipt/layout checks remain
failures; compilation/tests alone never permit visual DONE. No new core source or control access
is authorized by UI progress. Missing interfaces become proposals with unavailable states.

Historical workflow prose and native-model experiments remain in commits through 53ef5a3;
audit receipts and source projections are unchanged. Old model/host/branch instructions are not
active operating policy. Tauri and deployment are outside this consolidation.
